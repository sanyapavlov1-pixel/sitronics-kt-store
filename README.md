# Sitronics KT — интернет-магазин

Редактируемый B2B-каталог АО «Ситроникс КТ» с корзиной и оформлением заявки без онлайн-оплаты. Дизайн использует фирменные цвета, логотип и шрифт TT Firs Neue официального сайта Sitronics KT.

## Возможности

### Витрина
- каталог с поиском и фильтрацией по категориям;
- карточка товара с описанием, характеристиками, ценой и наличием;
- цена в рублях или вариант «По запросу»;
- корзина с изменением количества;
- B2B-заявка с контактами, компанией, ИНН и комментарием;
- адаптивная версия и PWA-манифест.

### Панель администратора
- вход по email и паролю с JWT-сессией в HttpOnly cookie;
- сводка по товарам, категориям и новым заявкам;
- создание, редактирование, скрытие и удаление товаров;
- цена, остаток, наличие, артикул, описания и характеристики;
- изображение по ссылке или загрузка JPG/PNG/WebP до 5 МБ;
- управление категориями;
- просмотр состава заявки и изменение её статуса.

## Стек

React 19, TypeScript, Vite, Tailwind CSS, Hono, tRPC, Drizzle ORM, MySQL/TiDB, TanStack Query, `vite-plugin-pwa`.

## Локальный запуск

Требуются Node.js 20+ и MySQL-совместимая база данных.

```bash
npm install
cp .env.example .env
```

Заполните `.env`:

| Переменная | Назначение |
|---|---|
| `APP_ID` | Идентификатор приложения |
| `APP_SECRET` | Длинная случайная строка для подписи JWT |
| `DATABASE_URL` | Строка подключения MySQL |
| `ADMIN_EMAIL` | Email администратора |
| `ADMIN_PASSWORD` | Пароль администратора, минимум 8 символов |
| `PORT` | Порт сервера, по умолчанию 3000 |

Для TiDB Cloud добавьте к `DATABASE_URL` параметр `?ssl={"rejectUnauthorized":true}`.

Создайте таблицы и загрузите стартовый каталог:

```bash
npm run db:migrate
npm run db:seed
npm run dev
```

Магазин: `http://localhost:3000/`  
Админка: `http://localhost:3000/admin`

Seed идемпотентен: он пропускает загрузку, если в каталоге уже есть товары.

Фирменные JPG-изображения и WOFF2-шрифты автоматически скачиваются с официального сайта Sitronics KT перед `dev` и `build`. Можно также восстановить их вручную командой `npm run assets:fetch`; скрипт проверяет SHA-256 каждого файла.

## Production

```bash
npm run check
npm run build
npm start
```

Сборка создаёт клиентскую часть в `dist/public` и серверный bundle `dist/boot.js`. Миграции находятся в `db/migrations` и должны применяться к новой базе до запуска seed. Для существующей базы не применяйте начальную миграцию повторно и не используйте деструктивный `db:push --force`.

## Docker

```bash
docker build -t sitronics-kt-store .
docker run --env-file .env -p 3000:3000 sitronics-kt-store
```

Перед запуском контейнера подготовьте базу командами `db:migrate` и `db:seed` из среды с доступом к ней.

## Изображения и объектное хранилище

Ссылки на изображения работают без дополнительных сервисов. Загрузка файлов использует объектное хранилище платформы Kimi и требует серверных переменных:

- `KIMI_AGENTGW_API_KEY`;
- `KIMI_AGENTGW_BASE_URL`;
- `KIMI_STORAGE_RESOURCE_ID`.

В Kimi они подставляются автоматически. В базе сохраняется storage key, а временный URL создаётся при отображении. Не переносите эти ключи в браузер и не публикуйте их в репозитории.

## Безопасность

- `.env`, реальные пароли и ключи исключены из Git и Docker-контекста.
- Админские процедуры проверяют JWT-сессию на сервере.
- Cookie: `HttpOnly`, `SameSite=Strict`, `Secure` в production, срок 8 часов.
- Стоимость и состав заказа рассчитываются сервером по актуальному каталогу.
- Входящие данные tRPC проверяются через Zod.
